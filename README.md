# Расчёт ресурсов и параметров Kubernetes-кластера

## Описание задачи

Необходимо определить требуемые ресурсы для проекта, состоящего из следующих компонентов:

* база данных,
* система кеширования,
* backend-приложение,
* frontend-приложение.

Приложение должно быть упаковано в **Helm-чарт** для деплоя в разные окружения.

- Требования: 
    1. Рассчитать необходимые ресурсы
    2. Определить количество рабочих нод Kubernetes-кластера
    3. Рассчитать резерв на отказ одной ноды с учетом служебных накладных расходов


## 1. Предполагаемая архитектура

* Для развертывания используется **Helm** с указанием параметров в `values.yaml`
* Stateless-компоненты (frontend, backend) — `Deployment`
* Stateful-компоненты (БД, кеш) — `StatefulSet`
* Отказоустойчивость обеспечивается несколькими репликами
* Для всех компонентов заданы `resources.requests` и `resources.limits`


## 2. Расчёт ресурсов по компонентам

### База данных

* Тип: StatefulSet
* Реплики: 3
* Ресурсы на 1 POD:

  * CPU: 1 core
  * RAM: 4 Gb

**Ресурсы с учетом количества реплик:**

* CPU: 3 core
* RAM: 12 Gb


### Система кеширования

* Тип: StatefulSet
* Реплики: 3
* Ресурсы на 1 POD:

  * CPU: 1 core
  * RAM: 4 Gb

**Ресурсы с учетом количества реплик:**

* CPU: 3 core
* RAM: 12 Gb


### Backend

* Тип: Deployment
* Реплики: 10
* Ресурсы на 1 POD:

  * CPU: 1 core
  * RAM: 600 Mb

**Ресурсы с учетом количества реплик:**

* CPU: 10 core
* RAM: 6Gb


### Frontend

* Тип: Deployment
* Реплики: 5
* Ресурсы на 1 POD:

  * CPU: 0.2 core
  * RAM: 50 Mb

**Ресурсы с учетом количества реплик:**


* CPU: 1 core
* RAM: 250 Mb

## 3. Суммарное потребление приложения

| База данных | 3 core      | 12 Gb        |
| Кеш         | 3 core      | 12 Gb         |
| Backend     | 10 core     | ~6 Gb         |

| **Итог:**   | **17 core** | **~30.25 Gb** |

## 4. Учёт служебных ресурсов Kubernetes

Необходимые накладные ресурсы для рабочих нод:

* kubelet
* container runtime
* kube-proxy
* системные демоны

Средние значения для worker-ноды:

* CPU: ~1 core
* RAM: ~1–1.5 Gb

---

## 5. Минимальный размер кластера без запаса

Предположим, что используются **worker-ноды** со следующими характеристиками:

* 8 CPU
* 32 Gb RAM

**Полезные ресурсы одной ноды (с учётом системных):**

* CPU: ~7 core
* RAM: ~30 Gb

### Расчёт:

* CPU: `17 / 7 ≈ 2.43`
* RAM: `30.25 / 30 ≈ 1.01`

Минимально требуется **3 worker-ноды**.

---

## 6. Запас на отказ одной ноды (N+1)

Кластер должен выдерживать выход из строя **как минимум одной worker-ноды**.

При отказе одной ноды:

* остаётся `N - 1` нод
* оставшиеся ноды должны вместить всю нагрузку

### Расчёт:

* Требуемо: 17 CPU и ~30 Gb RAM
* Одна нода даёт: ~7 CPU и ~30 Gb RAM

Минимально необходимо:

* `17 / 7 ≈ 2.43 → 3 ноды` **после отказа**

Следовательно:

* **общее количество worker-нод: 4**

---

## 7. Итоговая конфигурация кластера

### Worker-ноды

* Количество: **4**
* Параметры каждой ноды:

  * CPU: 8 core
  * RAM: 32 Gb

### Общие ресурсы кластера:

* CPU: 32 core
* RAM: 128 Gb

### Эффективно доступно под нагрузку (с учётом служебных):

* CPU: ~28 core
* RAM: ~120 Gb

---

## 8. Итог

Для развертывания приложения в Kubernetes с учётом отказоустойчивости, служебных ресурсов и запаса на отказ одной ноды требуется кластер из **4 worker-нод по 8 CPU и 32 Gb RAM**.
Данная конфигурация обеспечивает стабильную работу stateful- и stateless-компонентов и масштабируемость приложения в разных окружениях.
